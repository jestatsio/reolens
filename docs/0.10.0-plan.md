# Reolens 0.10.0 — plan

Theme: **"Drive it from anywhere local"** — a native command-line tool and MCP
server in the spirit of the official
[reolink-cli](https://github.com/reolink/reolink-cli), plus a full cleanup.
Decisions confirmed by the maintainer on 2026-11-16: native CLI + MCP (not a
bridge to the Reolink binary), breaking cleanup allowed, number stays a minor
(`0.10.0`, not `1.0.0`).

## Why not the Reolink binary itself

`reolink/reolink-cli` (v0.21.0) publishes only its agent skill, plugin
manifests, installers, and docs under Apache 2.0. The `reolink-cli` /
`reolink-gateway` binaries are proprietary under an EULA, the CLI source is
unpublished, and there is no iOS build. Bundling or shelling out to it from a
sandboxed App Store app is not viable, so 0.10.0 builds the same shape
natively on the contract Reolens already owns (`ReolensCore.CameraAPI`),
keeping the zero-dependency posture (`dependencies: []`).

## Architecture (mirrors reolink-cli → gateway)

| reolink-cli | Reolens 0.10.0 |
|---|---|
| `reolink-gateway` (session daemon) | Reolens for Mac with Local API on (`ReolensServer`, `/v1`) |
| `reolink-cli` (JSON client) | new `reolens-cli` executable |
| `reolink-cli mcp-server` (stdio) | `reolens-cli mcp-server` (stdio) |
| agent skill | documented in `docs/cli-mcp.md` (skill text can follow) |

New targets, all Foundation-only so parity holds at the contract level
(AGENTS.md §1, same carve-out shape as the Local API host):

- **`ReolensClient`** — `RemoteCameraAPI: CameraAPI` over HTTP `/v1` with an
  injectable transport (URLSession live, stub in tests; AGENTS.md §12).
  Includes the SSE events client.
- **`ReolensMCP`** — hand-rolled MCP (JSON-RPC 2.0 over stdio) core generic
  over `any CameraAPI`: `initialize`, `ping`, `tools/list`, `tools/call`.
- **`ReolensCLIKit`** — argv parsing + command dispatch returning
  `(exitCode, stdout, stderr)` so the whole CLI is unit-testable headlessly.
- **`ReolensCLI`** (product `reolens-cli`) — thin `@main` shell.

Auth: bearer token from `REOLENS_API_TOKEN` (copy it in Settings → Local
API); base URL from `REOLENS_API_URL` (default `http://127.0.0.1:8443`).
Tokens are never logged and never need to appear in argv (AGENTS.md §3/§11).
Output: JSON envelopes `{ok, command, data}` / `{ok:false, error}` by
default, `--output text` for humans. Exit codes: 0 ok, 1 API error,
2 usage, 3 server unreachable.

## Commands / tools (v1 = the existing CameraAPI surface)

`health`, `doctor`, `features`, `version`, `cameras list|show`,
`channels`, `capabilities`, `diagnostics`, `snapshot --file`,
`stream`, `ptz <op> [--duration-ms]`, `reboot` (requires `--yes`),
`recordings list|download` (metadata only — byte relay stays a later
phase), `settings get|set`, `events [--max-events N]`, `mcp-server`.
Camera selector: `--camera <id-or-exact-name>`, `--channel N`.

MCP tools mirror the same surface (`cameras_list`, `camera_snapshot`, …).
Snapshots return MCP image content. `camera_reboot` requires
`"confirm": true`. No streaming/event subscription tools in v1.

## Cleanup (breaking where it pays)

- `CameraDiagnostics`: stringly-typed status/transport become enums with
  identical raw values (Swift-API-breaking, wire-stable).
- `RemoteSmoke`: password moves off argv to env/`--password-stdin`.
- `PosixBcUdpTransport`: `print()` hex dumps → `os.Logger` (AGENTS.md §11).
- Health-auth documentation drift fixed to match the gateway's deliberate
  fail-closed behavior; token is copyable in Settings (not "shown once").
- Untrack `Scripts/__pycache__/*.pyc`; ignore `__pycache__/` + `.firecrawl/`.
- Stale 0.6.x audit docs archived under `docs/archive/`; ROADMAP refreshed.

## Deliberately deferred (needs camera hardware to validate)

Lights / siren / encoder / image-tune / users / Wi-Fi / firmware harvest
from reolink-cli (no Reolink wire models exist yet); Baichuan snapshot +
recording-search parity (0.9.1 deferral, needs a CX410-class device);
recording byte relay; MCP event subscriptions; HomeKit stays scaffolded
(MFi blocker unchanged — its flag is synced user state, not dead code).

## Security notes (AGENTS.md §3/§14)

Local API stays off by default, LAN-bound, bearer-authed. The CLI/MCP add
no new listeners and no non-Reolink network calls (§5). Snapshot files and
CLI output can contain LAN hosts (already exposed to authenticated `/v1`
consumers) — docs warn to redact before sharing. RTSP URLs with embedded
credentials remain unexposed (`LiveCameraAPI` omits them by design).
